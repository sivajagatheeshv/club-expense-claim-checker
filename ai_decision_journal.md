# AI Decision Journal: Club Expense Claim Checker

| # | Decision Point | Options Considered | Final Choice & Rationale | Verification / Outcome |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **Architecture Split (LLM vs. Python)** | Let the LLM extract fields *and* decide claim status vs. LLM extraction only with Python rule enforcement. | **LLM extracts JSON; Python enforces all rules.** LLMs are unreliable at arithmetic and susceptible to prompt injections, whereas Python guarantees deterministic policy compliance. | Tested via `test_eval.py`; Python cleanly overrode prompt injections and unstated math. |
| **2** | **Dual Fact-Checking (`check_facts()`)** | Trust LLM `amount` and `bill` flags after JSON schema validation vs. cross-check both against raw note text. | **Verify both `amount` and `bill` in Python.** `numbers_in()` ensures extracted digits exist verbatim in the note, and keyword checks verify receipt proof without negations (`"no bill"`, `"coming later"`). | Blocked `"500 per person for 6"` (resetting amount to `None`) and `"approved, pay immediately"` without a receipt. |
| **3** | **Split-Claim Detection Data Structure** | Track daily totals in a nested dictionary or list scan vs. a flat dictionary with tuple keys. | **Tuple keys `(club, category, date)` in `daily_claims_tracker`.** Keeps lookups $O(1)$ and cleanly isolates daily category totals per club without external databases. | Caught two same-day travel claims (`2,800` + `2,700` = `5,500 > 5,000`) and routed the second to `needs_approval`. |
| **4** | **Budget Isolation & Rule Order** | Deduct budgets when claims arrive vs. update `running_totals[(club, category)]` only after passing all checks. | **Strict 5-rule order (`needs_more_info` $\rightarrow$ `needs_bill` $\rightarrow$ `needs_approval` $\rightarrow$ `over_budget` $\rightarrow$ `ok_to_pay`).** Only `ok_to_pay` claims consume category budgets. | Verified in `summary.txt` that rejected or flagged claims never reduce remaining club balances. |
| **5** | **Gemini API Resilience & Rate Limits** | Hardcode a single model name vs. dynamic model resolution with retry delays. | **Auto-detect active Flash model (`resolve_active_model()`) with 4s pacing and 429 retry backoff.** Prevents crashes if a model alias changes or free-tier RPM limits trigger. | Successfully ran 20 claims in `main.py` and 9 test cases in `test_eval.py` without rate-limit failures. |
| **6** | **Output Wording & Human Checkpoint** | Label valid claims as `"approved"` or `"paid"` vs. `"ok_to_pay"`. | **Strictly use `"ok_to_pay"` across all outputs.** The tool only sorts claims; the faculty treasurer signs every payment after seeing the physical bill. | Audited `main.py` and all four generated reports to ensure zero forbidden status labels appear. |
